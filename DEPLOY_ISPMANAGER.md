# Развёртывание «Озёрск Рабочий» на shared-хостинге с ISPmanager

Пошагово, без SSH, только через панель ISPmanager и Файловый менеджер. Подходит для большинства тарифов «обычного веб-хостинга» (timeweb, beget, sprinthost, FirstByte, ihc.ru и т.п.) — нужно лишь, чтобы хостинг поддерживал Python 3.10+.

> Что мы получаем: рабочий новостной сайт по адресу `https://ozersk.example.ru` (вместо `example.ru` — ваш домен или поддомен), админка по `/admin/login`, БД и картинки — в папке `data/` рядом с сайтом.

## 0. Что нужно подготовить за минуту

1. **Домен или поддомен**, направленный на ваш хостинг. Например `ozersk.example.ru` через DNS A-запись, либо просто внутренний поддомен, который выдают хостинги (`xxx.beget.tech` и т.п.).
2. **Случайный секрет для cookie**. Откройте https://www.random.org/strings/?num=1&len=64&digits=on&loweralpha=on&upperalpha=on&unique=on&format=html&rnd=new — скопируйте получившуюся строку. Это будет `OZERSK_SECRET`.
3. **Пароль админа**. Придумайте (НЕ `admin`/`123` — мы потом всё равно сменим, но лучше сразу нормальный).

## 1. Создаём сайт в ISPmanager

В панели:

1. **Веб-домены** → **Создать веб-домен**.
2. В поле «Имя» введите ваш домен/поддомен, например `ozersk.example.ru`.
3. **Псевдонимы** — оставьте пустым.
4. **Корневая директория сайта** — оставьте по умолчанию (обычно вида `www/ozersk.example.ru`). Запомните этот путь — он понадобится. На большинстве хостингов он будет: `/var/www/USER/data/www/ozersk.example.ru` (где USER — ваш логин).
5. **Обработчик** / **Тип сайта** — выберите **Python** (на разных билдах ISPmanager пункт может называться «Python», «App via Passenger», «Python (Passenger)» — это всё одно и то же).
6. **Версия Python** — выберите **3.10**, **3.11** или **3.12** (любая из этих трёх).
7. **SSL** — пока «Без SSL», включим Let's Encrypt в самом конце.
8. **Создать**.

После создания сайта ISPmanager сам сделает базовую папку и `passenger_wsgi.py`-заглушку. Эту заглушку мы заменим на свою.

## 2. Загружаем код в корень сайта

Самый простой путь — без терминала, только через файловый менеджер.

1. Откройте https://github.com/VladiSLAVE1212/ozersk-rabochiy → зелёная кнопка **Code** → **Download ZIP**. Получится `ozersk-rabochiy-devin-1778427360-ozersk-rabochiy.zip` (название может отличаться).
2. В ISPmanager: **Файловый менеджер** → перейдите в корневую директорию сайта, которую запомнили в шаге 1.
3. **Закачать** → выберите скачанный zip → загрузите.
4. Кликните по zip правой кнопкой → **Извлечь** → согласитесь распаковать в текущую папку.
5. Внутри окажется папка вида `ozersk-rabochiy-devin-…/`. Зайдите в неё, выделите **всё содержимое** (Ctrl+A в файловом менеджере), **вырежьте** и **вставьте** на уровень выше (в корень сайта). Пустую папку и zip удалите.

В итоге в корне сайта должно лежать примерно так:

```
app/
scripts/
passenger_wsgi.py    ← это наш стартовый файл (он перезапишет тот, что сгенерировал ISPmanager)
requirements.txt
pyproject.toml
README.md
…
```

Если у вас всё-таки есть встроенная **Командная строка / Shell** в панели (на многих ISPmanager-хостингах есть), можно вместо шагов выше выполнить:

```bash
cd ~/data/www/ozersk.example.ru   # ваш путь
rm -f passenger_wsgi.py            # удаляем заглушку, созданную панелью
git clone https://github.com/VladiSLAVE1212/ozersk-rabochiy.git .
```

## 3. Указываем стартовый файл и устанавливаем зависимости

1. В ISPmanager откройте **Веб-домены → ваш сайт → ⚙ Изменить** (или раздел **Python** в боковом меню — зависит от билда).
2. **Стартовый файл / Точка входа / Application startup file**: `passenger_wsgi.py`.
3. **Объект приложения / Application Entry Point**: `application` (так уже по умолчанию).
4. **Файл зависимостей / Requirements file**: `requirements.txt`.
5. Нажмите **Сохранить**.
6. Найдите кнопку **Установить зависимости / Install requirements** (или «Применить»). Панель создаст venv и поставит всё из `requirements.txt`. Это займёт 30-90 секунд.
   - Если кнопки нет, но есть кнопка **Перезапустить** — Passenger сам поставит зависимости при первом запуске. Тогда переходите к шагу 4.

## 4. Прописываем переменные окружения

В том же разделе настройки сайта найдите секцию **Переменные окружения** (Environment Variables). Добавьте:

| Имя | Значение | Зачем |
|-----|----------|-------|
| `OZERSK_SECRET` | строка из шага 0.2 | подпись cookie сессий |
| `OZERSK_ADMIN_USER` | `admin` | логин начального админа |
| `OZERSK_ADMIN_PASSWORD` | пароль из шага 0.3 | пароль начального админа (используется только при первом запуске, дальше сменим) |
| `OZERSK_DB` | `/абсолютный/путь/к/data/ozersk.db` | где лежит SQLite-файл |
| `OZERSK_UPLOADS` | `/абсолютный/путь/к/data/uploads` | где лежат картинки |

Абсолютный путь — это путь корня вашего сайта + `/data/...`. Например: `/var/www/u1234/data/www/ozersk.example.ru/data/ozersk.db`.

Если страшно копаться с путями — просто **не задавайте** `OZERSK_DB` и `OZERSK_UPLOADS`, наш `passenger_wsgi.py` сам подставит безопасные дефолты в папку `data/` рядом с сайтом.

Сохраните настройки.

## 5. Создаём папку данных и проверяем права

1. В **Файловом менеджере**, в корне сайта, **Создать → Папка** → `data`.
2. Внутри `data` — ещё одну папку: `uploads`.
3. На обе папки правый клик → **Атрибуты** (Permissions / chmod) → выставите **0775** (или галочки «Запись» для владельца и группы). Владелец остаётся ваш пользователь.

Без этого SQLite не сможет писать БД, и аплоды картинок будут падать с 500.

## 6. Перезапускаем приложение

В ISPmanager: **Веб-домены → ваш сайт → Перезапустить** (или в разделе Python — кнопка **Restart**).

Откройте в браузере: `https://ozersk.example.ru/healthz` → должны увидеть `{"ok":true,...}`. Если так — всё взлетело.

Если 500 / «Что-то пошло не так» / Phusion Passenger error:

- Проверьте файл `passenger_wsgi.log` или **Логи** в ISPmanager (раздел **Веб-домены → Логи**), там будет питон-трейсбек.
- Самые частые причины: (а) не установился `a2wsgi` — нажмите **Установить зависимости** ещё раз; (б) у папки `data/` нет прав на запись — см. шаг 5; (в) опечатка в `OZERSK_DB`.

## 7. Заходим в админку и меняем пароль

1. `https://ozersk.example.ru/admin/login`
2. Логин/пароль из шага 4 (`admin` / ваш `OZERSK_ADMIN_PASSWORD`).
3. Перейдите по ссылке **Журналисты** в шапке админки.
4. У строки `admin` — кнопка **Сменить пароль** → введите новый длинный пароль → Сохранить.
5. Тут же создайте аккаунты для журналистов: логин, ФИО, пароль, галочка «admin» только для редакторов, которые должны иметь доступ к управлению пользователями.

## 8. Включаем HTTPS (Let's Encrypt)

В ISPmanager: **Веб-домены → ваш сайт → ⚙ Изменить** → раздел **SSL** → выбрать **Let's Encrypt** → **Сохранить**. Через 30-60 секунд сертификат выпустится. Также включите «Перенаправлять HTTP → HTTPS», чтобы все запросы шли по защищённому протоколу.

## 9. (опционально) Ускоряем отдачу статики

По умолчанию все запросы (включая `/static/*`) проходят через Passenger → Python. Это ОК для маленького сайта. Если хочется, чтобы статика отдавалась напрямую веб-сервером:

1. В ISPmanager: **Веб-домены → ваш сайт → Дополнительные директивы Nginx** (если ваш сайт на nginx) или **.htaccess** (если на Apache).
2. Для **Nginx** добавьте:
   ```nginx
   location /static/ {
       alias /полный/путь/к/корню/сайта/app/static/;
       expires 7d;
       access_log off;
   }
   ```
3. Для **Apache** в `.htaccess` корня сайта:
   ```apache
   Alias /static/ /полный/путь/к/корню/сайта/app/static/
   <Directory "/полный/путь/к/корню/сайта/app/static">
       Require all granted
   </Directory>
   ```

Перезапустите сайт.

## 10. Бэкапы

База данных и все картинки лежат в одной папке `data/` в корне сайта. Резервное копирование = архив этой папки. ISPmanager обычно имеет раздел **Резервные копии** — настройте автобэкап на эту папку с периодичностью, которая вас устраивает (раз в сутки — нормально для редакции).

## Если что-то идёт не так

| Симптом | Где смотреть | Что обычно лечит |
|---|---|---|
| 500 / `Application could not be started` | Логи Passenger в панели | Нажать «Установить зависимости», проверить, что в `requirements.txt` есть `a2wsgi` |
| 502 / nginx «Bad Gateway» | Логи nginx | Перезапустить приложение через панель |
| Постит 200 ОК, но при логине «Неверный логин» | Проверить `OZERSK_ADMIN_PASSWORD` в env | Перезапустить приложение **после удаления `data/ozersk.db`** — он создаст БД заново со свежим паролем |
| Картинка не загружается, ошибка 500 | Атрибуты `data/uploads` | Поставить запись (0775) |
| `[img]…[/img]` показывается как текст | Случайно отключили Python? | Откройте сам пост — если открывается простой HTML вместо нашего шаблона — сайт не запущен через Passenger |

Если совсем застряли — пришлите скриншот вкладки **Логи** в ISPmanager или текст ошибки, разберёмся.
